### 3. DAB (Dots & Boxes) - `api/game-logic/dab.js`

**Required Rules:**

- Who creates more boxes wins
- Custom size, player selection
- On making a box: extra move continues if multiple boxes claimed
- Redo move request valid only for the next player makes his/her move

**Current Implementation Issues:**

#### Issue 3.1: Redo Request Logic (Lines 191-234)

**Location:** `requestRedo()` method, lines 200-210

```javascript
const immediatePlayerIndex = room.currentTurn;
if (playerIndex !== immediatePlayerIndex) {
  // Error: Only current player can request redo
}
```

**Problem:** The current implementation allows ONLY the current player to request a redo. But the rule states "Redo move request valid only for the next player makes his/her move" - meaning the redo request should be valid while the next player hasn't made their move yet, not that only the current player can request it.

**Expected:** The player who JUST moved (the one whose move might be redone) should be able to request redo, OR the request should expire once the next player makes any move.

**Status:** NEEDS FIX - The undo logic should be tied to the previous mover, not the current player.

#### Issue 3.2: Multiple Box Extra Move (Lines 371-400)

### 4. Bingo - `api/game-logic/bingo.js`

**Resolved Rule Interpretation:**

- Both players have SEPARATE 5x5 boards with SHUFFLED numbers (1-25)
- Players share the SAME pool of scratched numbers
- When a number is called, BOTH players check if they have it and scratch accordingly
- Achieve 5-in-a-row/column/diagonal → scratch ONE letter from "BINGO"
- Need to scratch ALL 5 letters (B-I-N-G-O) by achieving 5 separate bingos to win
- 12 possible bingo lines per board (5 rows + 5 cols + 2 diagonals)
- Must check on EVERY move which player has new bingos

**Current Implementation Issues:**

#### Issue 4.1: Separate Boards Not Used Correctly

**Location:** `startGame()` and `markNumber()` methods

**Problem:** The current code generates separate boards correctly (line 109-116), but the win check only happens when `bingoAchieved()` is manually called. The game should:

1. Auto-detect when ANY player gets a bingo on each number call
2. Track which letters each player has scratched from "BINGO"
3. Broadcast that opponent scratched a number (so opponent knows their board state)

#### Issue 4.2: Win Condition - Should be 5 Separate Bingos

**Location:** `bingoAchieved()` method, lines 222-249

**Problem:** Current implementation requires 5 lines at once and checks only the caller's board. Should:

- Check BOTH players' boards on every number marked
- Track accumulated bingo count per player (0-5)
- Only the player who achieves their 5th bingo wins (if both hit 5 on same number, first to complete wins)

## Resolved Design Decisions (from Q&A)

### Bingo Win Condition & Boards

- **Board Setup:** Both players have SEPARATE 5x5 boards with randomly shuffled numbers 1-25
- **Shared Pool:** Same pool of scratched numbers applies to both players
- **Win Condition:** Each bingo (5-in-a-row) scratches one letter from "BINGO"
- **Game End:** First player to scratch all 5 letters (5 separate bingos) wins
- **Auto-Detection:** Must check both players' boards on EVERY number marked

### DAB Redo Request

- **Confirmed:** Previous mover can request redo (not current player)
- **Confirmed:** Redo request expires when next player makes ANY move
- **Confirmed:** After redo is accepted and undone, turn goes to the player who requested redo (they make a new move)

### UTTT Free Move

- **Confirmed:** "Won" grids with empty squares are still playable
- **Confirmed:** Free move given when target grid is full (can play in any grid)
- **Confirmed:** Free move NOT restricted on won grids - player gets free move if directed to a full grid
