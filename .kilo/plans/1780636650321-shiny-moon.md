# Plan: UI Consistency, Dark Mode, and Celebration Animations

## Objective

Audit backend/frontend mismatches, fix latent bugs, unify the UI across all games (dark mode, consistent info bars), and add lightweight win celebrations for UTTT mini-grid wins, DAB box completions, and SOS pattern formations. Connect4 and TTT do not need achievement-based mini-celebrations.

## Phase 1 — Discovery & Audit

### Audit Scope

- **Backend:** All 6 game managers in `api/game-logic/` (bingo, tictactoe, uttt, dab, sos, connect4) plus `BaseManager.js` and `api/index.js`.
- **Frontend:** All game pages in `pro/src/*/` and shared UI (`GameLayout.jsx`, `AvatarReactionBar.jsx`, `GameContext.jsx`, `ThemeContext.jsx`).

### 1C. Backend Bugs & Dead Code

1. **Every manager clears `this.clearTimer('forfeit_'+roomId)` on reconnect, but no manager ever registers a forfeit timer.** Dead-clear references in Bingo, TTt, UTTT, DAB, SOS, Connect4.
2. **Bingo `bingo_achieved` does not call `sendRoomInfo`** after setting `gameState = 'ended'` — clients receive stale room state after a self-declared win.
3. **Bingo `restartGame` sets `currentTurn = players[0]` unconditionally** — even if that player disconnected meanwhile.
4. **TTt has no `room.creator` field and no creator check on `restartGame`** — any player can restart at any time.
5. **DAB `redoRequestTimer` stored directly on room object** instead of `this.timers` — never cleared by `clearAllTimersForRoom`, survives room cleanup.
6. **DAB `startedWithPlayers` set in `startGame` but NOT reset in `restartGame`** — disconnect-pause logic uses stale snapshot.
7. **DAB `restartGame` assigns `gameState = 'waiting'` twice** (redundant).
8. **SOS board-size `<select>` `onChange` immediately calls `handleCreateRoom`** — room creation triggered on every dropdown change.
9. **SOS & Connect4 join buttons use `previousElementSibling` DOM traversal** to find room-ID input — fragile layout coupling.
10. **UTTT `reconnect` clears `forfeit_${roomId}` using a sanitized key** that was never registered (dead reference + casing mismatch).

---

### 1D. Frontend Bugs & Dead Code

1. **Critical: `GameLayout.handleLeave()` calls `socket.disconnect()`** — permanently destroys the socket. After navigating to any other game page, all socket events silently fail. Affects every game.
2. **Critical: TTt `ttt_moveMade` payload mismatch** — backend emits `{ position, symbol, board }` but frontend destructures `({ board, lastMove })`. `lastMove` is always `undefined`; the "last move" ring highlight is permanently broken.
3. **High: Dark mode infrastructure is dead code** — `ThemeProvider` never mounted; `ThemeToggle` never rendered; `data-theme` never set on `documentElement`. CSS `[data-theme='dark']` rules exist but never match.
4. **High: No frontend emits `requestRoomInfo`** — if the initial roomInfo broadcast is missed (e.g., late-connecting socket), clients have no recovery path even though every backend registers the listener.
5. **SOS & Connect4 join buttons** rely on `e.target.previousElementSibling` — breaks if DOM structure changes.
6. **Bingo turn timer does not pause** when `bingo_gamePaused` fires; `gameState` stays `'playing'` so the `useEffect` countdown continues.
7. **SOS lobby immediate creation bug** — board-size `<select>` `onChange` triggers room creation without clicking "Create".
8. **DAB optimistic `setLastMove` on click** runs before server confirmation — if the server rejects the move, the UI highlights a line that wasn't played.

## Phase 2 — Backend / Frontend Alignment

### A. Socket Event Payload Fixes

1. **Bingo `bingo_playerWon`** – Change emit from raw `socket.id` to `{ winner: string }` (object shape, consistent with TTt/UTTT/DAB/SOS/Connect4). Update frontend `Bingo.jsx` to destructure `{ winner }`.
2. **TTt `ttt_nextTurn`** – Change emit from raw `room.currentTurn` string to `{ nextPlayerId: string }`. Update frontend `TicTacToe.jsx` to destructure `{ nextPlayerId }`.
3. **DAB frontend** – Replace `socket.on('dab_redoCancelled', ...)` with `socket.on('dab_redoResponse', ...)` and handle both `accepted: true` (apply `dab_moveUndone`) and `accepted: false` (show reason via SweetAlert).

---

### B. Missing Backend Event Emissions

4. **DAB `dab_playerReconnected`** – Emit in `reconnect()` after `room.players[playerIndex].connected = true`: `this.io.to(sanitizedRoomId).emit('dab_playerReconnected', { playerId })`. Frontend already has the listener; it just never fires.
5. **All games** – Add `server_shutdown` handler in every backend manager's `handleConnection`: `socket.on('server_shutdown', () => { … })` — existing in `api/index.js` for global broadcast, but per-game disconnect flows should also listen.

---

### C. Frontend Missing Listeners

6. **DAB `dab_alert`** – Add in `DabGame.jsx`: `socket.on('dab_alert', ({ icon, title, text }) => Swal.fire({ icon, title, text }))`.
7. **SOS `sos_playerLeft`** – Add in `SOSGame.jsx`: update players list (mark disconnected), consider pausing game if activeCount drops.
8. **Connect4 `c4_playerLeft`** – Add in `Connect4Game.jsx`: update players list; pause if activeCount drops to 1 (backend handles pause broadcast, frontend should render it).
9. **All frontends** – Add `socket.on('server_shutdown', ...)` with friendly message + navigate home.
10. **All frontends** – Add `socket.on('<prefix>_requestRoomInfo', ...)` as a no-op or state-refresh handler (confirm no side effects; mainly so the backend's emit doesn't silently fail if an effect re-subscribes).

---

### D. State & Serialization Fixes

11. **UTTT `wonGrids`** – Replace `new Set()` with `[]` in `api/game-logic/uttt.js`. Update all usages: `.has()` → `.includes()`, `.add()` → `.push()`, `.delete()` → `.filter()`. In `sendRoomInfo`, pass `wonGrids: [...room.wonGrids]` to ensure a JSON-safe copy.
12. **DAB `redoRequestTimer`** – Move from `room.redoRequestTimer` to `this.timers` with key `redo_${roomId}`. Clear in `respondRedo` and `clearAllTimersForRoom`. Implement the missing `setTimeout` in `requestRedo` so redo requests auto-expire.
13. **DAB `sendRoomInfo`** – Replace `{ ...room }` with an explicit clean-object that omits `redoRequestTimer` and any other DOM- timeout / non-serializable values.
14. **DAB `restartGame`** – Add `room.startedWithPlayers = room.players.length` to prevent stale pause logic on reconnect.

---

### E. Gameplay Logic Fixes

15. **Bingo `bingoAchieved`** – After `room.gameState = 'ended'`, call `this.sendRoomInfo(sanitizedRoomId)` before emitting `bingo_playerWon` so clients receive fresh state.
16. **Bingo `restartGame`** – Clear `this.clearTimer('turn_'+roomId)` and `this.clearAllTimersForRoom(roomId)` before resetting state.
17. **TTt `createRoom`** – Add `room.creator = socket.id`. **TTt `restartGame`** – Add `if (room.creator !== socket.id) return;` (silent, matching other managers).
18. **Bingo `bingo_gamePaused` frontend** – Set `gameState` to `'paused'` (or add pause overlay) so the timer `useEffect` stops counting down. Resume to `'playing'` on `bingo_nextTurn` or `bingo_gameRestarted`.

---

### F. Creator / Restart Authority Unification

19. **Frontend pattern** – All games should derive `isCreator` from `room.creator === socket.id` and gate restart/start buttons on `isCreator`. Currently TTt uses `myPlayerIndex === 0`; update to `isCreator`.
20. **Backend verification** – Confirm Bingo, UTTT, DAB, SOS, Connect4 all enforce creator checks on `restartGame` and `startGame`. (They already do; TTt is the only outlier after fix #17.)

---

### G. Frontend `requestRoomInfo` Recovery Fallback

21. **Every game frontend** – Add a `useEffect` that emits `<prefix>_requestRoomInfo` on mount when `roomId` exists but room state has not yet been received (use a `roomLoaded` ref set to `true` after the first `roomInfo` / `gameState` / `gameStarted` event). This provides recovery if the server's join broadcast was missed.

---

### H. `GameLayout` Socket Disconnect Fix (Critical)

22. **`GameLayout.handleLeave()` must NOT call `socket.disconnect()`**. Replace with:
    - Emit the game's `<prefix>_leaveRoom` event (pass the `gamePrefix` via shared GameContext prop or context variable).
    - Call `clearRoomId()` from GameContext.
    - Call `navigate('/')`.
    - **Do not destroy the socket.** The same socket instance is reused when the user enters another game.

---

### I. Dark Mode — Wire Up Existing Infrastructure

23. **Mount `ThemeProvider`** in `pro/src/index.jsx` wrapping `GameProvider`.
24. **Render `ThemeToggle`** in `GameLayout.jsx` header so it's visible in every game view.
25. **`ThemeProvider` sets `document.documentElement.dataset.theme`** on mount and on toggle — existing `[data-theme='dark']` CSS in `pro/src/index.css` will then activate automatically across all games.
