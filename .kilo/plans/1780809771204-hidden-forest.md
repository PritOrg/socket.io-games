# Comprehensive Error Handling Implementation Plan

## Overview

Implement robust error handling across backend (API) and frontend (React) for all games, focusing on reconnection scenarios and edge cases.

---

## Backend (api/game-logic/)

### 1. BaseManager.js Enhancements

**Current Issues:**

- No try/catch around socket operations
- No validation alerts for missing rooms/players on reconnection
- No error boundaries for unhandled exceptions

**Changes:**

```
- Add try/catch wrapper to handleConnection registration
- Enhance handlePlayerLeave with error alerts
- Add validateReconnectData method with error feedback
- Add onSocketError helper method for logging and alerting
- Wrap all timer callbacks in try/catch
- Add room state validation before critical operations
```

### 2. Game Manager Reconnect Enhancements

**Each game manager needs:**

- Validate roomId/playerId on reconnect before processing
- Send specific alert if room not found vs player not found
- Handle case where room exists but was deleted during reconnect
- Handle case where player already reconnected (different socket)
- Send alert if reconnecting to ended/expired game
- Clear all game-specific timers on reconnect attempt (even if fails)

### 3. Reconnection Edge Cases

**Scenarios to handle:**

1. Player tries to reconnect with wrong roomId format
2. Player tries to reconnect to non-existent room
3. Player tries to reconnect with wrong playerId
4. Player already reconnected (duplicate reconnect)
5. Room game state changed during reconnect (ended/paused)
6. Reconnect to a room in 'waiting' state (not playing)
7. Reconnect after room was cleaned up by empty timer
8. Reconnect while room is being restarted

### 4. Error Events to Emit

Add consistent error alerts:

```
- invalid_reconnect_data: Malformed reconnect payload
- room_not_found: Room doesn't exist
- player_not_found: Player ID not in room
- game_already_ended: Cannot reconnect to ended game
- reconnect_failed: General reconnect failure with reason
```

2. **Auto-clear on failure** - Clear session storage automatically when reconnect fails
3. **Distinguish disconnect types** - Different handling for temporary vs permanent disconnects

---

## Implementation Notes

### Reconnect Retry Logic

- First retry: immediate (within 1s)
- Second retry: 2s delay
- Third retry: 4s delay
- After 3 failures: Alert user and clear storage

### Session Storage Clearing

- Clear on: room_not_found, player_not_found, game_already_ended
- Preserve on: transient network errors (retry scenarios)

### Disconnect Type Distinction

- `temporary` (network disconnect): Allow reconnect, show "Reconnecting..." UI
- `permanent` (leaveRoom): Clear storage, show "You left the game" message
