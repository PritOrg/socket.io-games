# Bug Fix Plan — Frontend-Backend Connection, Data Mismatches, Polishing

## High Priority (Bugs)

### 1. Bingo `playerLeft` handle mismatch

- **File**: `api/game-logic/bingo.js:422`
- **Issue**: `handlePlayerLeft` callback emits `this.io.to(roomId).emit('bingo_playerLeft', socket.id)` (raw socket ID), while frontend (`pro/src/bingo/Bingo.jsx:200`) expects an object destructured as `({ playerId })`.
- Other lines in the same file (e.g., `leaveRoom`) correctly emit `{ playerId: socket.id }`.
- **Fix**: Emit `{ playerId: socket.id }` consistently.

### 2. UTTT `wonGrids` Set serialization

- **File**: `api/game-logic/uttt.js:119`, `332-344`, `460-472`
- **Issue**: Room stores `wonGrids: new Set()`. When emitted via Socket.IO, JSON.stringify converts `Set` to `{}`.
- `sendRoomInfo` and `emitGameState` spread the raw room, leaking the non-serializable Set.
- **Fix**: Strip `wonGrids` from emitted room objects (it's already server-side-only logic).

## Medium Priority (Data / Connection Mismatches)

### 3. Dab create/join missing avatar fields

- **File**: `pro/src/dab/DabGame.jsx:70-77` (create), `80-93` (join)
- **Issue**: `handleCreateRoom` and `handleJoinRoom` omit `avatarIcon` and `color`. Backend (`api/game-logic/dab.js:26,96`) destructures these; they arrive as `undefined`.
- **Fix**: Forward `profile.avatarIcon` and `profile.color` in both emits.

### 4. Socket listener re-subscription on roomId/state changes

- **Files**: `pro/src/bingo/Bingo.jsx:241`, `pro/src/dab/DabGame.jsx:273`, `pro/src/uttt/UTTTGame.jsx:239`
- **Issue**: Socket listener effect dependencies include `roomId`, `rows`, `cols`, `players`, causing the entire listener block to tear down and re-register whenever those state values change. React dependency churn.
- **Fix**: Narrow dependencies to `socket` only (use refs for latest room/player values inside handlers).

### 5. Stale `sessionStorage` reconnect data on rematch / replay

- **Files**: `pro/src/bingo/Bingo.jsx:297`, `pro/src/dab/DabGame.jsx:141-169`, `pro/src/uttt/UTTTGame.jsx:285-288`, `pro/src/sos/SOSGame.jsx:119-121`
- **Issue**: After `restartGame`, the frontend doesn't clear sessionStorage in some games. Client may try to rejoin the old room session on next launch.
- **Fix**: Clear sessionStorage on `gameRestarted` events alongside `gameOver`/leave.

### 6. Unused / dead timer fields on room objects

- **Files**: `api/game-logic/tictactoe.js:61-62`, `api/game-logic/uttt.js`, `api/game-logic/connect4.js`, `api/game-logic/sos.js`
- **Issue**: Rooms declare `emptyTimer`, `forfeitTimer` as properties but `BaseManager` uses `this.timers` Map. The per-room timer refs are never set or cleared, making them misleading and potentially stale.
- **Fix**: Remove unused room properties or delegate fully to `registerEmptyTimer` / `clearTimer`.

## Low Priority (Polish)

### 7. Frontend handle fallback redundancy

- **Files**: `pro/src/connect4/Connect4Game.jsx:50`, `pro/src/bingo/Bingo.jsx:95`, `pro/src/dab/DabGame.jsx:122`
- **Issue**: reconnect logic does `p.id || socket.id` where `p.id` is always identical to `socket.id` in normal flow. Adds noise.
- **Fix**: Simplify to `socket.id` or just use the player lookup directly.

### 8. React deprecated `onKeyPress`

- **Files**: `pro/src/connect4/Connect4Game.jsx:286`, `pro/src/sos/SOSGame.jsx:282`
- **Issue**: `onKeyPress` is deprecated.
- **Fix**: Use `onKeyDown`.

### 9. Inconsistent `sendRoomInfo` sanitization

- **Files**: `api/game-logic/connect4.js:368-372`, `api/game-logic/dab.js:541-547` (already sanitizes), `api/game-logic/bingo.js:432-443` (strips timers), `api/game-logic/uttt.js:457-472`
- **Issue**: Some managers send raw room objects with internal props visible to clients; others sanitize. Inconsistency risks leaking implementation details.
- **Fix**: Apply sanitizer pattern uniformly across all `sendRoomInfo` / `emitGameState`.

### 10. Bingo board display mapping noise

- **File**: `pro/src/bingo/Bingo.jsx:166`
- **Issue**: `typeof n === 'string' ? n : n` is a no-op tautology in the map callback.
- **Fix**: Simplify to a direct `strikedNumbers.includes(n) ? 'X' : n` guard.
