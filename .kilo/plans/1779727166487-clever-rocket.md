# Codebase Consistency Improvements Plan

## Overview

This plan addresses inconsistencies identified across the Socket.IO Games monorepo, focusing on server-side game managers and frontend patterns.

## Issues Identified

### 1. Room Info Sanitization Inconsistency

**Files affected:** `api/game-logic/*.js` (TicTacToe, Dab)

- **Bingo & UTTT:** Properly sanitize room info before emitting (`sendRoomInfo` removes timer references)
- **TicTacToe:** Sends raw room object without sanitization
- **Dab:** Sends room object directly without sanitization

**Fix:** Standardize `sendRoomInfo` to sanitize sensitive/timer properties from all managers.

### 2. Socket Event Logging Inconsistency

**Files affected:** `api/game-logic/*.js`

- **UTTT:** Logs all socket events with `logger.socket()`
- **Bingo, TicTacToe, Dab:** No socket event logging

**Fix:** Add consistent socket logging to all managers for debugging parity.

### 3. Player Name Validation Inconsistency

**Files affected:** `api/game-logic/*.js`, `pro/src/context/GameContext.jsx`

- **Backend:** `BaseManager.validatePlayerName()` exists but is only used in Bingo's join flow
- **TicTacToe, UTTT, Dab:** Create/join don't validate player names
- **Frontend:** No validation before sending player names

**Fix:** Apply consistent player name validation in all managers and optionally frontend.

### 4. Disconnect Handler Inconsistency

**Files affected:** `api/game-logic/*.js`

- **Bingo:** Uses `handlePlayerLeave` from BaseManager with custom callback
- **TicTacToe:** Custom disconnect handler, doesn't use BaseManager's `handlePlayerLeave`
- **UTTT:** Custom disconnect handler, doesn't use BaseManager's `handlePlayerLeave`
- **Dab:** Custom disconnect handler, doesn't use BaseManager's `handlePlayerLeave`

**Fix:** Standardize disconnect handling to use BaseManager's `handlePlayerLeave` pattern.

### 5. Turn Timer Management Inconsistency

**Files affected:** `api/game-logic/bingo.js`, `api/game-logic/tictactoe.js`, `api/game-logic/uttt.js`, `api/game-logic/dab.js`

- **Bingo:** Has 30-second turn timer with proper cleanup
- **TicTacToe:** No turn timer
- **UTTT:** No turn timer
- **Dab:** No turn timer

**Fix:** Either add turn timers to all games for parity, or document that Bingo is special-cased.

### 6. Creator Property Inconsistency

**Files affected:** `api/game-logic/*.js`

- **Bingo, Dab:** Have `creator` property on room
- **TicTacToe, UTTT:** No `creator` property (uses turnOrder[0] for first player)

**Fix:** Standardize room structure - either add `creator` to all or remove from all.

### 7. Game State Transition Inconsistency

**Files affected:** `api/game-logic/*.js`

- **Bingo:** `waiting` → `ready` → `playing`
- **TicTacToe:** `waiting` → `playing` (auto-start on join)
- **UTTT:** `waiting` → `playing` (auto-start on join)
- **Dab:** `waiting` → `playing` (manual start)

**Fix:** Decide on standard flow - "ready" state should exist where game requires explicit start.

### 8. Frontend Socket Reconnection Handling

**Files affected:** `pro/src/context/GameContext.jsx`

- No reconnection logic when socket disconnects
- Player loses room state on disconnect

**Fix:** Add socket reconnection with room state recovery.

### 9. Missing Server Games in index.js

**Files affected:** `api/index.js`

- SOS and Connect4 game files exist but are not imported/registered in `index.js`
- Frontend has SOS and Connect4 routes but server doesn't support them

**Fix:** Either implement server support for SOS/Connect4 or remove frontend routes.

### 10. SOS/Connect4 Server Integration Missing

**Files affected:** `api/index.js`

- SOS and Connect4 manager files exist but are NOT imported/registered in `api/index.js`
- Frontend has working components and routes for both games
- Tests exist for both games but server support is missing

**Fix:** Add `SOSManager` and `Connect4Manager` imports and registration to `api/index.js`.

### 11. Room Info Sanitization Missing in SOS/Connect4

**Files affected:** `api/game-logic/sos.js`, `api/game-logic/connect4.js`

- Both managers send raw room object without sanitization in `sendRoomInfo`
- Neither has `creator` property in room structure consistency check

**Fix:** Standardize `sendRoomInfo` sanitization.

### 12. Frontend Socket Logger API Mismatch

**Files affected:** `pro/src/utils/logger.js`, `pro/src/utils/useSocketLogger.js`

- Frontend logger.js uses unicode arrow symbols ('⬅️') for direction
- Backend logger.js uses string 'IN'/'OUT'
- Frontend `useSocketLogger` hook exists but may not match backend format

**Fix:** Align socket logging format between client and server.

## Implementation Priority

1. **Critical:**
   - SOS/Connect4 server integration (broken functionality - routes lead to 404)
   - Room info sanitization (data leakage prevention)
   - Room creation alert missing in TicTacToe

2. **High:**
   - Socket event logging parity
   - Player name validation consistency
   - SendRoomInfo sanitization in SOS/Connect4

3. **Medium:**
   - Disconnect handler standardization
   - Creator property standardization
   - Turn timer consistency

4. **Low:**
   - Game state transition logic
   - Socket reconnection enhancement
   - Frontend logger alignment

- `api/game-logic/tictactoe.js` - Add sanitization, logging, room creation alert

### Frontend

## Expected Outcomes

1. All games work through complete create/join/play lifecycle
2. Consistent error handling and user feedback across games
3. Cleaner data transmission (no internal timer references exposed)
4. Better debugging capabilities with consistent logging
5. Validated player names prevent injection/errors
