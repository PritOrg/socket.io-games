# Maintain Similarity Across All Games — Implementation Plan

**Plan ID**: 1779694981863-cosmic-island  
**Goal**: Make Bingo, TicTacToe (TTT), Ultimate TicTacToe (UTTT), and Dots & Boxes (DAB) feel like a single cohesive family of games with consistent UX, code patterns, error handling, and reuse of shared components.

**User Decisions Recorded** (from clarification):

- Start-game model: **Keep current split** (explicit "Start" for Bingo/DAB; auto-start on 2nd player for TTT/UTTT).
- Error contract: **Standardize on `_alert` with `{ icon, title, text }`** (deprecate `_error` in UTTT).
- Shared components: **Aggressively adopt** (full integration of `useGameHandlers`, `RoomLobby`, `TurnIndicator`, `MatchReport`, `AvatarSelector`, `CountdownOverlay`, improved `GameLayout`).
- Room ID generation: **Standardize on short UUID** (Bingo style) via BaseManager.

---

## 1. Executive Summary

Four games were added incrementally. Despite a rich set of shared UI components and a `BaseManager`, each game has duplicated:

- Socket event wiring and state syncing
- Room creation/join/start/leave/reconnect flows
- Error presentation
- Turn indication and post-game screens
- Inline lobby UIs instead of `RoomLobby`

Result: Inconsistent player experience and high maintenance cost.

This plan enforces **similarity** by:

- Fixing backend contracts (events, logging, room ID, error shape)
- Refactoring all four games to use shared hooks + components
- Extracting remaining common logic into BaseManager and frontend hooks
- Updating tests to verify consistency

**Scope**: api/ + pro/src/ (no new games, no database).

## 2. Current Inconsistencies (Evidence-Based)

- Aggressive adoption is explicitly requested.

## 3. Goals & Non-Goals

**Goals**:

- Single error/alert contract (`_alert`) across backend + frontend.
- All games use short-UUID room IDs generated in BaseManager.
- All games use `useGameHandlers` (enhanced) for create/join/start/leave.
- All games route pre-game through `RoomLobby` (adapted per game needs).
- All games use `TurnIndicator` + `GameLayout` as the single source of navigation/turn UI.
- Post-game uses `MatchReport` (or a lightweight consistent variant).
- Backend: rich logging parity, consistent use of BaseManager helpers, no dead code.
- Tests cover the shared paths (not just game-specific logic).

**Non-Goals**:

- Changing game rules or balance.
- Forcing explicit Start button on TTT/UTTT (per user decision).
- Adding new games or major new features.
- Database or persistence.
- Perfect visual pixel-perfect identity (game-specific boards stay unique).

## 4. Work Breakdown (Prioritized)

### Phase 0 — Contracts & Foundation (High Confidence, Low Risk)

1. **BaseManager — Room ID & Helpers**
   - Add `generateRoomId()` using `uuid` (already a dep).
   - Enhance `handleReconnection` so it can be the single implementation (or document why games still need overrides).
   - Add `clearAllTimersForRoom(roomId)` helper.
   - Add optional `onLog` or ensure managers can use a shared logger category.

2. **Standardize Error Contract**
   - Change all UTTT `_error` emissions to `_alert` with proper `{icon, title, text}` shape.
   - Update frontend listeners in UTTTGame.jsx (and any generic error toast logic).
   - Add deprecation comment in BaseManager for any old patterns.
   - Update API tests that assert on `uttt_error`.

3. **Logging Parity**
   - Add lightweight logger calls (info/warn on critical paths) to Bingo, TTT, DAB managers using the same style as UTTT.
   - Do not over-log every move unless DEBUG.

4. **Frontend Hook Enhancement**
   - Update `useGameHandlers` to:
     - Accept an optional `leaveRoomEvent` or emit `<prefix>_leaveRoom` before disconnect (current games do this).
     - Support "soft leave" (emit leave event, clear local room state, stay connected for other games) vs hard disconnect.
     - Make Swal use `sketchPopupClass` (currently missing in the hook).
   - Update its test.

### Phase 1 — Backend Refactors (Per-Game, Parallelizable)

For each manager (order: TTT → UTTT → DAB → Bingo for easiest first):

- Replace room ID generation with `this.generateRoomId()`.
- Replace all error emissions with `_alert`.
- Replace hardcoded event strings in TTT with template + prefix.
- Refactor `reconnect` to call (or be replaced by) BaseManager `handleReconnection` where possible.
- Replace inline leave/disconnect logic with `handlePlayerLeave` + callbacks.
- Remove dual emission paths in UTTT (`emitGameState` → consolidate to `sendRoomInfo` emitting `uttt_roomInfo`; update frontend).
- Ensure all managers emit consistent `*_roomInfo`, `*_gameStarted` / `*_gameRestarted`, `*_playerLeft`, `*_gamePaused`, `*_alert` shapes.

**Deliverable**: All four managers pass existing tests + new "consistency" tests (see Testing section).

### Phase 2 — Frontend Aggressive Adoption (Largest Effort)

**2.1 Shared Layout & Navigation**

- Improve `GameLayout` to own the top nav, room copy, player avatars (using `PlayerBadge` or `AvatarSelector`), and authoritative Leave flow.
- Remove all duplicate Leave buttons from the four game components.
- Pass `gamePrefix`, `onLeave`, and any game-specific actions as props/children slots.

**2.2 Pre-game / Lobby Unification**

- Integrate `RoomLobby` into all four games.
  - For Bingo/DAB: support "Start" button when ready + host-only.
  - For TTT/UTTT: hide Start (auto-start), show "Waiting for opponent..." state.
- Extend or compose `ModeSelector` for DAB's four modes + player count (or keep a small DAB-specific wrapper).
- Wire `AvatarSelector` (optional ink color) — store in sessionStorage alongside reconnect data.
- Add `CountdownOverlay` on game start where it makes sense (host-triggered starts).

**2.3 In-Game Feedback**

- Replace all custom turn text/spinners/timers with `<TurnIndicator>` (pass player name, isActive, isMyTurn, turnTimer).
- Bingo keeps its 30s countdown but renders it via the shared indicator.
- Ensure dimming of board when not your turn is consistent (or opt-in per game).

**2.4 Post-Game**

- Replace "Play Again" + basic Swal with `<MatchReport>` (winner, scores, optional stats like moves/time).
- Keep "Play Again" (restart) and "New Room" actions.

**2.5 Reconnection & State**

- Create (or enhance) a `useReconnection` hook that centralizes:
  - sessionStorage key pattern (`${prefix}_reconnect`)
  - emit on mount
  - cleanup on unmount / room leave
- Update all four games to use it.

**2.6 Code Size & Duplication Targets**

- DAB: target reduction from ~900 lines toward 500-600 by moving mode UI to components + using shared lobby/handlers.
- Other games: 30-50% reduction in boilerplate.

**Files touched (approximate)**:

- pro/src/components/ui/GameLayout.jsx (enhance)

- New or enhanced: `useReconnection.js`
- All four game files (Bingo.jsx, TicTacToe.jsx, UTTTGame.jsx, DabGame.jsx) — heavy edits

### Phase 3 — Polish, Edge Cases, Documentation

## 6. Risks & Mitigations

- **Risk**: Aggressive adoption changes UX for players mid-session.  
  **Mitigation**: Feature-flag the new lobby per game behind a dev toggle initially, or roll out one game at a time (TTT first as simplest).

- **Risk**: `useGameHandlers` leave semantics differ from current per-game nuance (especially DAB redo state).  
  **Mitigation**: Enhance the hook with options; keep game-specific `onLeave` callbacks for complex cases.

- **Risk**: DAB's complexity (zoom-pan, redo, variable sizes) makes full extraction harder.  
  **Mitigation**: Accept some DAB-specific UI inside the shared shell; extract only the outer flow.

- **Risk**: UUID change could theoretically collide with existing short random IDs (extremely unlikely).  
  **Mitigation**: Document; no migration needed (in-memory only).
